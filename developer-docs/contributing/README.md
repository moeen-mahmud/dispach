# Contributor guide

Dispach welcomes focused pull requests. The most useful contributions fix a reproduced failure,
close a documented gap, improve an example, or make an existing contract clearer.

You can submit a bug fix or documentation improvement directly. Discuss these before writing code:

- a new dependency or package;
- a public API, manifest field, event type, or wire change;
- a change to architecture, persistence, security behavior, or product scope;
- a performance claim that needs a new evaluation method.

Start with [development setup](development-setup.md), then use the
[repository map](repository-map.md) to find the owning package. [Making a change](making-a-change.md)
explains which specifications and checks move with different kinds of work.

Security reports follow [the private reporting process](../../SECURITY.md). Maintainers alone cut
releases; [releasing](releasing.md) documents that process so it is reviewable rather than tribal
knowledge.
